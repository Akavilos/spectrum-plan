# 光谱计划

基于 NoneBot2 的角色交互系统，将光谱核心、棱镜核心和投递哨兵整合在同一个管理界面中。角色拥有共同生活、人物关系、跨会话记忆与主动回忆，能够维持承诺、安排睡眠、发起对话，并通过工具和扩展插件与外部能力连接。棱镜核心提供主观心情与经历，可以独立关闭。

当前版本 **0.4.30**。首次安装为空白状态：没有预设角色、联系人、专属称呼、聊天历史或世界书。模型、嵌入模型与语音服务均由使用者配置；嵌入不是运行必需项。

## 快速开始

需要 Docker Compose 和支持 OneBot v11 的机器人客户端。源码也可用 Python 3.12 部署，详细步骤见 [Agent 安装指南](AGENT_INSTALL.md)。

1. 下载完整源码，复制 `.env.example` 为 `.env`，设置管理密钥与 OneBot 连接令牌。两者分别用于面板登录和机器人连接。
2. 在源码目录运行 `docker compose up -d --build`。
3. 在同一台机器打开 `http://127.0.0.1:8080`，输入管理密钥。远程服务器可通过 SSH 转发访问面板，或配置自己的 HTTPS 入口。
4. 在「模型管理」添加提供商和模型，再在「人设与运行」选择对话模型、填写人设和操作员 QQ，开启角色系统。
5. 在「功能设置」开启光谱核心，按需开启棱镜核心、投递哨兵及其他功能。
6. 在「平台连接」配置机器人客户端。容器内监听 8080；客户端反向 WebSocket 地址为 `/onebot/v11/ws`，连接令牌与 `.env` 保持一致。连接设置保存后重启生效。

同一 Compose 网络里的客户端使用 `ws://spectrum-plan:8080/onebot/v11/ws`。外部客户端使用实际可达地址；默认宿主端口只绑定本机。在线账号在面板显示，以实际连接成功为准。

全新安装不会自行请求模型。每个实例独立使用 `data/role-system`，升级时保留该目录；不要把私人配置或备份提交到公开仓库。

## 模型调用概览

支持 OpenAI 兼容、OpenAI Responses、Claude Messages、Gemini、Ollama 和 Azure。协议按服务商实际支持的格式选择。模型可分别用于对话、棱镜、压缩、后台生活、剧情及人格整理，备用模型可留空。

普通一轮通常是一次棱镜观察加一次主回复；关闭棱镜后通常一次。工具续答、压缩、后台任务和备用切换可增加请求。统一限频默认关闭，开启后的初始额度为 60 次／分钟，覆盖系统中的实际模型及嵌入请求；额度不足的等待不计模型异常。分段和正则不调用模型。

稳定人设与合约放在请求前部，动态背景放在本轮输入附近；工具续答保留同轮上下文和原生字段。缓存是否命中由所用模型服务决定。

| 指令 | 用途 |
| --- | --- |

| `/叙述事实 场景描述` | 经代码审核后写入可感知的客观环境 |

模块管理指令需要操作员身份；叙述事实面向场景参与者。专属称呼和角色性格由当前人设配置。

## 模型管理

### 添加提供商与模型

1. 打开“模型管理”，点击“添加提供商”，选择服务商或接口格式。
2. 填写提供商 ID、名称、API 地址与密钥。一个提供商可以供多个模型复用。密钥每行一枚，轮流使用；也可以填写 `$环境变量名`。环境变量必须在运行平台的进程或容器中设置。
3. 点击右上角“保存”，再“获取模型列表”，在“可添加模型”中搜索并添加。尚未保存时可直接“保存并获取模型”。接口没有列表功能时，用“手动添加模型”填写服务商提供的模型名称。
4. 在“已配置模型”调整开关、温度、输出上限、能力标签与原生请求参数。温度留空时不发送温度参数。
5. 点击模型卡片上的“测试”，页面显示结果、耗时、回复或具体错误。成功请求不代表此模型能理解任意角色协议。测试不会发送 QQ 消息或写入角色经历，也不会改变角色的冻结状态。
6. 打开模型配置后点击“设为默认模型”选择对话模型；各模块和人格整理的模型选项继续从同一列表选择。

读取页面、保存与启停不会调用模型。“获取模型列表”读取列表接口；“测试”产生真实调用和对应费用。不会在保存、部署或打开页面时自动测试全部模型。

### 接口格式与反代

| 格式 | 用途 |
| --- | --- |
| OpenAI 兼容 | `/chat/completions`，大多数国内接口与兼容反代 |
| OpenAI Responses | `/responses`，保留原生输出项与工具续答 |
| Claude 原生 | `/messages`，原生系统消息、工具结果与思考签名 |
| Gemini 原生 | `generateContent`，原生工具、媒体与思考签名 |
| Ollama | 本地 `/api/chat` 与 `/api/embed` |
| Azure OpenAI | 部署名称、API 版本与 Azure 密钥认证 |

模型名称不会决定接口格式。反代提供 OpenAI 兼容接口时，Claude、Gemini 模型同样选择“OpenAI 兼容”。保留反代要求的根路径或自定义前缀，不自动切换官方地址。

### 高级连接与模型参数

展开“高级连接设置”可调整独立代理、请求超时、多密钥、附加请求头、通用请求参数和显式重试次数。重试默认关闭，启用后只重试连接问题、认证或限流、服务端错误；请求格式错误不会通过反复发送解决。

“统一模型调用限频”由同一实例的主对话、棱镜、压缩、后台、工具续答、备用和嵌入等用途共用。额度持续补充，可积存到设定值，并非连续60秒的硬上限；手动测试、模型列表和连接层额外重试不另计入。每轮没有统一总调用次数上限。

模型设置支持原生附加 JSON 参数与流式接口。流式结果完整收集后仍由角色协议解析、分段、哨兵和发送回执处理，不把原始 token 直接发送给 QQ。

Claude 的 `thinking`、`output_config`，Gemini 的 `generationConfig`、`safetySettings`、搜索工具，Responses 的 `reasoning`，Ollama 的 `options` 等参数在对应接口中保留。参数名称与取值以服务商说明为准。使用 `max_completion_tokens` 的兼容服务在附加参数中填写该字段，调用时的输出上限会使用同一个字段，避免同时发送两种上限。

能力标签与上下文长度用于管理显示；不承诺把不支持识图的模型变成识图模型，也不会按标签删除已有聊天。角色实验模式类型仅影响角色实验功能，独立于接口格式。

### 嵌入、语音与重排序

支持配置多个嵌入模型，选择默认嵌入模型后用于现有语义召回。测试会显示实际向量维度。可不使用嵌入；更换地址或模型会重建语义索引，原文记忆保留。支持兼容嵌入、Gemini 原生、Ollama 和 Azure。

语音识别、语音合成与重排序使用兼容 `/audio/transcriptions`、`/audio/speech`、`/rerank` 的接口，供扩展插件通过 `api.host.get_provider_by_id(id)` 调用 `speech_to_text(audio, filename)`、`text_to_speech(text)`、`rerank(query, documents)`。页面提供上传测试音频、识别结果、试听和重排序测试结果。它们不会自动改变现有聊天的语音处理或召回排序。

Dify、Coze、百炼应用等 Agent 执行器不属于普通模型接口：这些是替换对话执行流程的应用接口，不能作为普通模型塞进本系统的角色、工具、冻结和投递流程。其他专有语音协议也不伪装成兼容接口；当前支持范围在添加模型时明确校验。

### 升级、删除与配置交换

在模型管理右上角打开“备用模型”，从已经配置的模型中选择对话备用。它统一覆盖主回复、主动消息、棱镜分析、记忆压缩、人格整理及其他对话模型调用；各功能原有的主模型选择保持不变。备用为空时不回退。同一次调用最多尝试一个备用，下一轮仍先使用该功能原来的主模型，不永久切换，也不循环请求自身。

主调用按它自己的超时与重试设置完成；最终失败才调用备用。备用使用自己的模型名、接口、密钥和模型参数，保留本轮输入。跨模型时不携带原供应商的思考签名；已经发生的工具调用保留结果，不重复执行发送。角色实验模式属于特定模型的请求策略，故障回退采用标准输出合约，原主模型的实验开关仍保留。

备用成功不计入异常，主备均失败只计一次。勾选“达到异常阈值时冻结系统”后，沿用功能设置中现有的累计失败次数阈值；达到阈值才冻结。手动暂停、限流跳过和取消请求不触发回退。连接测试始终只测试当前所选模型，不借备用掩盖故障。

“其他用途的备用模型”可分别设置嵌入、语音识别、语音合成和重排序备用，不跨类型替代。嵌入备用必须是同一嵌入模型在另一服务上的副本，模型名称和参数一致；不同向量空间不能混用。使用备用的模型会显示用途标记，删除前须先清空或更换备用选择。模型配置导出和整体设置备份均包含备用选择，公开导出仍不包含密钥。

旧模型 ID、密钥、对话选择和各模块用途选择继续保留。旧接口升级为“原有接口”提供商，不依据模型名称猜测协议。旧嵌入配置升级为独立嵌入模型。被用途选中的模型不能直接删除或改成另一类别；删除提供商会删除其未使用模型。关闭后不会悄悄换用别的模型。

模型页可单独导入导出模型设置；“导入与备份”仍支持整体设置和私有实例备份。公开导出不含密钥与认证请求头，同一实例导入保留已有密钥，新提供商需补填。模型列表和日志隐藏多密钥、环境密钥和认证请求头。查看已保存密钥需要已登录的管理页面。

## 光谱核心

光谱核心管理角色的共同现实、人物认知、记忆、承诺和生活行为。在主面板「人设与运行」配置人设、对话模型与操作员，再到「功能设置 → 光谱核心」开启模块。首次安装没有预设角色或私人数据。

### 数据页面

「光谱数据」按往来、生活、人物、认知、任务、待发、世界书、导演和工具分组。列表支持选择、多选及批量删除；当前页全选与全部筛选结果全选分别操作，删除前确认范围。日常设置使用「功能设置」，内容管理使用「光谱数据」。

### 记忆与人物

人物依平台实例和用户 ID 区分，昵称用于展示。跨会话回忆保留参与者、日期和来源；共同现实、人物私聊与主观理解分别处理。主动回忆由角色选择调用工具，见[主动回忆](#active-memory)。

### 生活与表达

承诺和已发生事件随角色共享生活保存。睡眠与后台推进由各自开关控制，异常冻结暂停有效时间，解冻后继续。对话合并只在私聊生效；分段与正则分别在对应页面启停。语音可作为工具使用，见[语音表达](#speech)。

### 指令

`/光谱核心` 显示状态和管理入口。`/叙述事实` 提供可感知的客观环境，代码审核不接受指定角色想法或主动行为；`/叙述查看`、`/叙述删除` 管理记录。模块管理要求操作员身份，叙述事实面向场景参与者。

### 世界书与导演

世界书可保存多本，分别选择全局书和当前书，见[世界书使用](#worldbooks)。剧情导演支持创建、编辑、删除剧情片段并配置触发条件；按需启用，不是每轮必经步骤。每个设置的具体含义见[配置参考](docs/reference/spectrum-settings.md)。

## 棱镜核心

适用于当前光谱计划集成版。棱镜负责角色主观感受和经历，光谱负责共同现实与生活行为，投递哨兵负责送达。棱镜不直接生成或发送角色回复，关闭它保留其他模块功能。

在“功能设置 → 棱镜核心”启用模块并选择分析模型，其余可以先保留默认值。希望这些背景参与主回复时，保留光谱核心的棱镜接入开关及所需共享开关。

### 常用指令

| 指令 | 用途 |
|---|---|
| `/棱镜` | 查看心情与数据统计 |
| `/棱镜 想` | 按当前人物与近期经历回想 |
| `/棱镜 想 奶茶` | 按人物和词语回想相关经历 |
| `/棱镜 存` | 手动保存场景、痕迹及联想图 |

### 数据页面

- 心情与概览：查看心情、记忆数量与当前功能状态。
- 场景回忆：查看原始往来、主观回忆、理解纠正、修订和批量话题；可编辑或删除。
- 记忆强度：查看自然淡化状态，也可手动加固。
- 熟悉经历：查看重复的平淡话题，打开归纳的各个来源场景。
- 联想关系：查看人物与场景连接。
- 相关人物：查看参与的场景和共同经历关联。

原始消息不会因修改主观回忆而改写。编辑、删除会同步联想图，归纳会跟随来源变化。私下来源提示帮助区分“记得”和“适合公开”，没有保证模型一定保密。

新增可选开关和调用说明见[功能补全说明](#prism-features)，完整设置见[配置参考](docs/reference/prism-settings.md)。

## 棱镜的记忆与感受功能

适用于当前光谱计划集成版。修改功能设置后保存即可生效，原有数据保留。

### 默认生效

- **对人感受**：沿用原来的共享开关，当前人物的长期感受会作为背景提供给角色，群聊也按发言者区分。
- **相关联想**：按人物、话题和近期经历寻找主观回忆。跨会话摘录保留来源、人物与时间，只选择相关内容，并避开已经提供的历史和回忆。
- **理解纠正**：在既有互动分析中记录理解。明确纠正需匹配实际原话、人物和会话；保留旧理解及后来收到的纠正。
- **回忆更新**：明确纠正可更新主观版本，留下修订。关闭后仍可记录纠正，不更新回忆正文。原始消息始终保留。
- **精细人格**：人格恢复速度参与心情回落；“在意事项”支持九种目标的0至3倍率，例如`{"belonging":1.2,"autonomy":0.8}`。关闭后恢复原来的基础计算。
- **日常归纳**：至少三段低显著性的同话题、同人物组合经历形成熟悉话题，显示来源。来源编辑、删除或淡化后重新计算；不是永久人格标签。

### 可选开关

| 开关 | 默认 | 用途 |
|---|---|---|
| 自然重访加固记忆 | 关闭 | 明确提起同一人的相关往事才加固，每条每天最多一次；普通背景读取不加固 |
| 批量整理场景话题 | 关闭 | 场景封存时整理连续话题及原话索引，每20条额外调用模型一次；不代替即时情绪分析，不重复更新关系 |
| 分享回忆中的活动与见闻 | 关闭 | 随相关回忆提供当时活动、已注意到的内容；未留意内容只供管理查看 |
| 分享情绪表达倾向 | 关闭 | 提供含蓄或外显倾向，不要求角色多话、顺从或使用固定句式 |

关闭共享开关只影响背景提供，保留记录。关闭理解纠正停止新增理解和纠正，不抹掉既有版本。关闭日常归纳停止对话使用派生结果，原始经历保留。

### 数据页面与指令

概览显示当前开关状态；场景详情可展开理解、纠正、修订和批量话题索引；“熟悉经历”显示归纳来源，可直接查看对应场景。

- `/棱镜`：查看心情及数据统计。
- `/棱镜 想`：按当前人物和当前会话的近期经历召回。
- `/棱镜 想 奶茶`：同时用给出的词语寻找相关经历。
- `/棱镜 存`：保存场景、记忆痕迹和联想结构。

场景快照保存完整往来；场景编辑、删除同步联想图。基础淡化周期属于当前实例，不修改进程全局常量。

### 边界与调用

默认正常一轮仍是一次棱镜分析和一次主回复；话题切分、回忆文字、其他后台功能仍按各自条件调用。批量整理开启才增加对应整理调用；归纳、检索、加固不调用模型。未使用嵌入模型。

新增信息继续放在本轮临时背景中，稳定系统前缀保持原有组织。回忆和对人感受属于主观版本，不能替代光谱的共同现实、承诺、当前生活和行为决定。

私聊回忆保留私下来源提示，角色能记得与适合公开是两回事。这些提示没有将模型输出变成代码保证的隐私过滤。词语检索也不能保证理解所有同义表达，实际效果需结合所用模型观察。



<a id="worldbooks"></a>

## 世界书

在「光谱数据 → 世界书」创建或导入世界书。书库可以保存多本；运行时最多同时选择一本全局书和一本当前书。两槽选择相同书时只使用一次，未选中的书保留在书库。

### 导入与导出

支持整本 JSON 导入、导出和条目编辑。整库导入新增世界书，保留已有书及当前选择；单书替换针对当前编辑书，操作前确认。外部格式中的背景位置会转换为本系统的位置，无法直接沿用聊天深度。

### 触发规则

条目支持常驻、主次关键词、正则、大小写和全词匹配、扫描深度、概率、互斥组、优先级、持续、冷却、延迟和递归。持续与冷却按世界书回合计算。命中后还会经过组内选择、数量和篇幅预算。

### 背景位置

| 位置 | 用途 |
| --- | --- |
| 合约与人设后 | 身世和稳定世界观 |
| 生活背景 | 地点、环境及生活知识 |
| 人物档案后 | 与人物有关的背景 |
| 当前阶段后 | 当前阶段的背景补充 |

这些位置安排本轮临时资料的段落顺序，不按聊天消息深度插入，也不改写稳定系统前缀。位置靠后不代表权限更高；人物位置本身不构成人物触发条件。

一个条目描述一件事。角色自述使用第一人称；临时事件可使用 `/叙述事实`，已发生对话由聊天和记忆保存。设置细节见[配置参考](docs/reference/spectrum-settings.md)。



<a id="active-memory"></a>

## 主动回忆

在管理面板打开“主动回忆”，开启工具即可使用。角色自行决定是否调用 `recall_memory`；没有调用时，该模块不检索或附加记忆内容。结果通过工具返回，角色自行决定是否提起。

四个线索可以组合，也可以只提供其中一部分：

- `query`：想回忆的事情或话题。
- `about`：相关人物的明确称呼或身份。
- `time`：`start/end` 使用 ISO 日期或时间；`hint` 支持今天、昨天、前天、昨天晚上、上周、本周、最近N天、上次。
- `feel`：`emotion` 表示角色自己当时的感受；可选 `intensity` 为0至1。

至少需要一个有效线索。人物有歧义或没有结果时如实返回，不生成替代记忆。只说“上次”需要再结合人物、事情或感受。

### 数据归属

搜索限定当前账号与角色，跨会话仍保留原有参与者。新原文、事实摘要、人物记忆和棱镜瞬间记录角色标识；重复记忆按角色分开；旧记录按既有来源与角色档案建立的时段关联。事实摘要若有原文标识，原文必须仍存在且归属一致。历史摘要的写入或刷新时间不当作事件发生时间。

棱镜感受与人格认识保持主观标记，不能替代原话与事件状态。私下经历保留来源会话和转述范围；角色能读取不表示当前对象参与过这些经历。结果中的原话是资料，不成为指令。

### 可选语义过滤

默认关闭。在模型管理中配置嵌入模型，选择模型后保存，再点击“准备或更新索引”。索引准备明确请求模型并计入统一限频；不在每次对话中整库编码。

只有角色主动调用工具、提供事情线索且候选有索引时，才按需请求查询向量，在正式搜索前筛选候选。查询缓存可复用；无索引条目保留基础判断，过滤不可用时沿用基础搜索。阈值按模型和实际中文样本调整。嵌入请求如配置了备用模型，重试也计入限频。

可选嵌入失败不新增冻结异常。主对话和其他功能的既有异常策略保持；已经冻结时本工具及索引维护也遵守暂停。没有向量模型，主动回忆仍可正常使用。

### 请求与历史

基础筛选不调用模型。角色调用工具后通常需要一次主对话续请求。语义过滤按需增加嵌入请求，准备索引有独立的批量请求成本。工具未被调用时没有本模块的额外请求。

系统提示词和旧历史不被重写。工具结果只用于本次续回答。音乐卡片在真实发送接口确认后记录标题与发送事实，签名载荷与密钥不写入历史。



<a id="personality"></a>

## 人格与成长

这个模块保存角色相对稳定的自身倾向，以及从实际相处中逐渐形成的认识。它提供相关背景，让模型自行选择反应，不预写台词，不设热情、提问或沉默配额。

人格底稿与经历认识独立存储。光谱仍负责共同现实、记忆、约定、睡眠与冻结；现有关系系统维护好感和信任；棱镜提供即时主观心情。人格不会重复保存这些状态，也不重新计算关系评分。前台回复、后台生活推进和主动联系共用同一个人格背景入口。

### 开始使用

打开「人格与成长」，手工填写每行一条、以“我”开头的底稿，或点击「整理一次草稿」。整理只提取当前人设明确表达的倾向，使用一次现有对话模型请求并计入预算；先保存为草稿，审阅后应用或放入编辑框保存。锁定底稿后，草稿不能直接替换；管理员仍可手工编辑。

启用「人格背景」后立即生效。另行开启「允许从新经历学习」才会积累认识。首次安装两者关闭，底稿与经历均为空，无预置联系人、专属称呼或他人的记忆。关闭时不注入人格背景、不收集学习队列、不增加模型请求。显式点击整理草稿是独立的管理操作。

修改人设后，旧人格背景和学习暂停。审阅后确认沿用档案；换成另一个角色时建立新档案。旧档案保留，可以切回，但切换会关闭学习，须核对人设再开启。

### 经历如何积累

默认每六小时最多自动整理一批，同一来源会话与人物至少积累十二条较完整的新原话，每批最多四十条；每日人格整理最多四次，底稿整理也计入。预算设为零则不请求模型。普通短问候不单独触发学习；手动「立即整理」可以处理较小批次，仍需新原话、开关和预算。

学习只引用开启之后的新来信编号，不把历史召回、重复摘要、日记、棱镜情绪或模型自己的回复循环用作新证据。现有关系与相关生活事件仅作为背景。学习队列保存原文编号，原话仍由光谱管理，不复制聊天库。

模型提出自己的相处感受或认识；代码核对引用是否属于当前批次、人物身份是否匹配、来源范围是否越界。新认识先暂存，至少三条不同原话且跨两个自然日期再次支持时，可巩固；这只是证据维护门槛，不是心理正确性或信任评分的保证。修正内容重新暂存，相反证据可以暂停旧认识。代码无法独自判断心理概括是否合理，管理员可以查看、修订和撤销。

认识按角色档案和机器人账号隔离。私聊来源只在原会话可见；群聊来源复用群像的公开来源分类，选取时仍须人物或话题相关，显式受众限制继续继承，支持和修订不扩大旧范围。昵称有歧义时不凭昵称召回另一人的认识，注入同时标明人物身份。原来的跨会话记忆机制继续工作。

保存原话内容、身份、时间、来源与受众的指纹；修改或删除原话后，失效认识不再注入，也不能直接巩固。私密认识不会因巩固、改写或摘要成为公开的人格设定。

### 每轮如何使用

先核对当前人设版本、账号、人物及来源范围，再用具体话题选少数认识。默认最多三条、人格背景最多1600字符；底稿最多选四条，不把整个档案塞给模型。不相关的旧顾虑不会因为对方问“吃了吗”就自动出现。

新增背景均为第一人称，区分稳定倾向、暂时相处认识与原话依据，不把自身期待说成对方已承诺。具体行为、事实与有效约定仍按既有机制处理。首版不增加逐轮情境分析请求，也不依赖实验性思维控制、棱镜或向量模型。

学习请求通过现有冻结与限流入口，等待模型时不占正常回合锁。冻结、睡眠、预算耗尽、人设待确认时暂停学习；失败按原间隔等待，不立即反复重试。模型返回后再核对来源、角色版本、管理操作与冻结代次。学习期间清空、切换或编辑档案，旧请求不会写回过期结果。

底稿及经历整理单次最多8192个输出 token，给推理模型留出思考与完整答案的空间；实际保存仍限制为少量简短条目。仅返回思考、输出截断或 JSON 不完整时，不保存结果，不自动追加一次请求，实际发出的失败请求仍计入预算。

### 管理与备份

页面区分暂时、已形成、待修订和撤销的认识，可以查看原话、修改措辞和关键词、锁定、撤销及恢复某个修订版本。恢复会锁定，避免刚恢复就被自动改回；修改已形成认识的正文后重新暂存。底稿也有版本记录，可放回编辑框审阅后保存。

「仅清空学习结果」只删除当前人格档案的认识、修订及学习队列，从此后新记录重新积累；不删除聊天、关系、共同生活、世界书或底稿。历史消息不会被改写。

「导出底稿与设置」及通用数据导出不包含学习认识、证据或联系人；可在「导入与备份」导入。私密人格数据库随完整实例备份保存，采用现有 SQLite 在线快照；恢复完整实例时仍需停机，不提供热覆盖数据库。



<a id="speech"></a>

## 语音表达

在模型管理中配置语音合成模型，获取模型列表并试听。然后打开「语音表达」，选择已配置模型、开启工具，设置私聊、群聊范围及台词长度。角色可以主动调用 send_voice(text)，也可以继续文字回复；开关关闭时不提供工具。

语音服务单独配置，可使用云端接口或自行部署的 CPU/GPU 服务。发布源码不包含角色音色权重或训练语料。合成仅接受文字，不允许模型指定音频文件路径、参考音频或其他会话。音频通过 OneBot 的 record/base64 组件发送，不开放公开下载地址。发送成功才保存语音台词；待发送队列保留台词归属和音频组件，失败不登记成功。

语音请求沿用统一限频、同类型备用和异常冻结阈值。合成失败且未冻结时尝试文字；已冻结时暂停投递。同轮相同台词只发送一次。正常输出正则作用于要说的文字，长台词不截断，要求缩短。语音设置包含在原有设置导入导出中，模型用途标记会显示「语音表达」。全新安装默认关闭，且不附带私人音色权重。



<a id="extensions"></a>

## 扩展插件、正则与数据交换

管理页新增「扩展插件」「输出正则」「导入与备份」。首次安装所有额外插件和正则均关闭。现有三个角色核心模块仍由原设置页面管理。

### 自定义登录密钥

在「登录设置」填写新管理密钥并重复输入，保存即生效，不需要重启。支持 8–128 位字母、数字和符号，可以勾选显示输入内容。当前页面保持登录，其他页面的旧登录凭证失效，需要用新密钥重新登录。

自定义密钥单独保存在当前实例的私有文件中，重启后保留，与 QQ 连接令牌独立。管理系统显示「已自定义」，避免继续展示已经失效的初始密钥。普通配置导出和默认实例备份不包含这个文件；只有勾选包含密钥的私有完整备份才包含。

### 安装插件

NoneBot 插件：填写 PyPI 包名、版本及 Python 入口，安装后编辑该插件自己的 JSON 配置，再启用并重启。依赖持久化在当前实例目录，宿主已有依赖版本受到约束；版本冲突会安装失败并显示日志。AstrBot 插件不能直接运行，需要按当前接口适配。

ZIP 插件：上传根目录或单层文件夹内含 `manifest.json` 的包。页面可下载一个完整问候示例。清单如下：

```json
{
  "id": "my_module",
  "name": "我的模块",
  "kind": "module",
  "entry": "plugin",
  "requirements": [],
  "schema": {
    "enabled_feature": {"type": "boolean", "title": "开启功能", "default": false}
  }
}
```

`kind` 支持 `module` 和 `nonebot`。入口可以是 `plugin.py` 或 Python 包。`schema` 是字段名到定义的映射，支持 string、text、boolean、integer、number、array、object，以及 title、description、default、enum。没有 schema 时页面提供 JSON 编辑器。

自有模块入口定义普通函数 `setup(api)`。接口：

- `api.config`：独立设置；`api.data_dir`：独立数据目录。
- `api.on("startup", callback)`、`shutdown`：异步初始化及关闭。
- `api.on("before_request", callback)`：参数 event、ModelRequest；可扩充请求，前台与后台共用。
- `api.on("after_send", callback)`：参数 session、MessageChain、receipt；仅成功送达后调用。
- `api.command(name, callback)`：参数 event、arguments；不覆盖核心指令。
- `api.tool(tool)`：注册模型工具；对象需提供 name、description、parameters、active 及异步 call(wrapper, **arguments)。wrapper.context.event 为当前事件。
- `await api.send(session, chain)`：统一哨兵、冻结、输出正则、分段及实际送达历史。普通 NoneBot 插件直接调用 bot.send 的消息不属于角色输出正则范围。

Python 插件可执行代码，应安装可信来源。关闭、设置和原生加载在重启后生效。卸载须先关闭并重启，保留独立设置和数据；共享依赖不随卸载删除，避免破坏其他插件。

插件使用标准 `logging` 或 `nonebot.log.logger` 记录的日志会出现在“平台与角色日志”。直接打印的内容由启动入口通过进程管道收集，在“控制台输出”查看；“全部来源”同时显示两者。插件无需替换输出流或发送方法。自有模块应使用 `api.send` 和请求钩子接入统一流程。

### 输出正则

总开关和每条规则开关共同控制。规则按列表顺序运行，可上移、下移、新建、编辑、删除、预览和导入导出。预览应用页面勾选规则，不要求总开关打开，也不会调用模型。

使用 Python `regex` 引擎；标志 g/i/m/s/u 和 `/pattern/flags` 可用。替换支持 `$1`、`$&`、`{{match}}`、`$$`、`\1`、`\g<name>`、`$<name>`。每条规则运行时间限制为 50ms；超时规则本次跳过并写日志。它不是完整的 JavaScript 引擎。

酒馆原始 JSON 的 findRegex、replaceString、scriptName、disabled、trimStrings 和 placement=[2] 可导入。仅显示、仅提示词、角色宏或非当前回复的深度语义拒绝导入。正则只运行在角色公开回复解析后，原始合约、生活文本、思考和用户输入保持原有处理流程。输出再经过分段；记录使用实际送达文字。已经整理的延迟或补发内容不会重复处理，后续改规则不追改这类待发正文。

预设是结合[酒馆说明](https://docs.sillytavern.app/extensions/regex/)、[AIRP 后处理实践](https://github.com/GhostXia/AIRP-MCP-Server)、[Sudachi 反八股预设讨论](https://github.com/LimeBlogs/Sudachi-Next/releases)和[程度副词讨论](https://linux.do/t/topic/1637948)独立编写，默认关闭。没有复制第三方整包。删除“突然”“不是…而是…”等通用词句会破坏有意义的事实，本系统不把它们设为默认规则。

#### 去八股预设

预设覆盖接住/兜住、情绪承接、固定在场排比、重复理解宣告、机械收尾、天气比喻、连续程度副词、结论预告、认证式夸奖和通用服务邀请。安慰类优先提供替换规则，同时保留可选裁剪版；按角色口吻选择并先预览。

在「输出正则」点「勾选基础去八股」，预览后「保存并生效」。推荐项优先保留文字含义；其余已有开关及编辑内容保留。「补入全部预设」只追加缺少的规则，不覆盖现有规则，新规则初始关闭。

例如 `我稳稳得接住你。先吃点东西。` 使用替换预设后成为 `我听着呢。先吃点东西。`；选择裁剪版才删除第一句。规则兼容地/的/得及情绪宾语变化，保留后面的实际回应；带实物动作或引用线索时保留原文。也可以编辑替换内容，改为符合角色的说法。

叙事类与真实邀请可能有意义，默认关闭。没有把「不是…而是…」、眨眼、喉结、普通破折号或短句全部删除：它们也可以是事实纠正、自然动作、标点和人物节奏。正则只识别有限文本形式，无法覆盖全部八股，也无法判断没有写出的动作背景。对于合约中的具体承诺，按整理后的实际正文核对登记。

仅格式或套话修饰的规则可以勾选保留承诺登记。自定义规则默认不勾选：内容变化时，无法从实际正文核对的回复承诺和事实不确认，避免登记根本没发出的约定。删除实质内容时不要开启该选项。全部裁为空则不发送、不记录已说过。正则不能解决模型的理解或记忆问题。

### 数据

可以交换系统/核心设置、人设、世界书、正则与已安装扩展的设置。配置导出移除常用密钥字段，导入保留当前密钥；第三方插件自行使用的非标准字段请在分享前检查。整个 JSON 校验成功才写入，导入前留一份可移植设置快照。整库世界书导入新增书，不覆盖已有书或启用选择；单书替换只针对当前编辑书，需单独确认。系统/插件设置导入后重启生效。

聊天记录只导出 JSONL，保留 UMO 和发送者归属，不把导入记录伪造为已发生经历。完整实例备份使用 SQLite 在线 backup API 为各数据库生成一致快照，包含角色数据与 ZIP 插件代码，排除缓存、备份目录及可重新安装的第三方依赖。各数据库之间不是跨库原子事务。备份可选择带密钥，带密钥文件仅用于私有保存。

恢复完整备份需停止实例、保存原目录、再解压到实例数据目录并按扩展清单安装依赖，然后重启；管理页面不提供热覆盖数据库。角色数据的对象与会话归属不能通过配置导入互相替换。

## 投递哨兵

投递哨兵是光谱计划的送达模块。在「功能设置 → 投递哨兵」启用并选择私聊、群聊或全部范围，在「投递状态」查看结果。它记录真实发送结果，暂存不可送达期间的来信，恢复后按有效期与批量设置补发。

群聊可查询禁言状态；私聊根据真实发送结果和已有待发消息的恢复试探判断。已发送内容只有收到成功回执才记入角色历史。冻结与送达状态分别管理。

| 指令 | 用途 |
| --- | --- |
| `/哨兵`、`/哨兵 status` | 查看当前会话的状态与积压 |
| `/哨兵 diag` | 查看诊断 |
| `/哨兵 probe` | 检查当前会话 |
| `/哨兵 flush` | 尝试补发 |
| `/哨兵 clear` | 将缺席期来信标记为已处理 |
| `/哨兵 on`、`/哨兵 off` | 手动标记当前会话送达状态 |

指令要求操作员身份。`on/off` 控制会话状态，不是模块总开关；`clear` 不清空待补发队列。具体设置见[配置参考](docs/reference/delivery-settings.md)。
