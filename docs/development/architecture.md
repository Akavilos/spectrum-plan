# 集成版运行边界与缓存约定

## 接入原则

不运行时替换 NoneBot、协议适配器、模型供应商或自有事件的发送方法。不读取框架私有连接容器，不覆盖第三方函数代码、类或全局输出流。角色的完整控制由自己的 Host、Provider、RoleSystem 与 Event 接口负责。

发送成功、分段失败、冻结、哨兵暂存及补发的确认发生在统一发送端。增加新的发送组件时，通过编码器与文本来源登记接入，不能给外部对象打补丁。

## 模型请求顺序

1. 稳定人设与输出合约；普通聊天和后台生活采用相同顺序。
2. 结构化的历史来信与实际送达回复。
3. 本轮共同生活、人物资料、召回、世界书、主观心情和人格认识，再加当前输入。
4. 使用公开协议的实验角色续写材料，仅在对应开关与接口能力满足时启用。

工具续请求从实际输入序列接续，原样保留本轮临时资料、媒体及供应商返回的原生工具消息。工具结果加入本轮序列，不把动态背景移动到末尾重新提出用户请求，不持久化临时背景或模型原生推理字段。

人设、合约、角色模式、工具配置修改，或历史窗口批量移动时，相关前缀会发生有意变化。当前动态背景从本轮输入处开始变化，不应误称为每轮整个缓存失效。平台默认近期历史至少 30 条，十条一批移动；光谱历史模式按四轮一批移动。两种模式仍独立提供长期记忆与跨会话来源。

模型用量日志保留供应商返回的 usage；缺失字段不等于零。缓存由供应商和代理实现决定，不承诺固定命中率。

## 日志与插件扩展

平台和角色日志采用公开的 logging Handler 与 NoneBot 日志 sink。打印内容由 `run.py` 的 stdout/stderr 管道读取，机器人进程无需修改自己的输出流。收集器单独轮转 console.log，界面可以切换来源；所有读取、下载继续受管理页面认证约束。

Python importlib 加载自有扩展、NoneBot load_plugin 加载原生扩展，以及设置公开 driver.config 都是正常接入方式，并非替换框架函数。原生插件配置赋值方式见 [NoneBot 配置文档](https://nonebot.dev/docs/appendices/config)。第三方 Python 插件与宿主同进程运行，安装未知插件不能自动获得安全性或资源隔离保证；自有模块应通过请求、工具和发送接口协作。

## 维护与检查

新接入代码需明确其调用时机和结果归属，不依赖捕获任意内部请求。变更请求构造时检查工具续请求及后台回合；变更发送时检查部分送达与冻结；变更日志入口时检查控制台打印、信号退出、认证与密钥隐藏。

官方缓存资料：[DeepSeek 上下文缓存](https://api-docs.deepseek.com/guides/kv_cache/)、[Gemini 上下文缓存](https://ai.google.dev/gemini-api/docs/caching)。
