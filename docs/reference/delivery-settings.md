# 投递哨兵配置参考

与当前管理界面的设置字段一致。

## 开始使用

先开启投递哨兵并选择保护范围。默认的检查、恢复和补发参数可直接使用；它与光谱核心的生活冻结分别控制。

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 启用投递哨兵 | false | 检查 QQ 消息是否真正送达，已知无法发送时暂缓模型回应，并保留待补发内容。适用于 OneBot/aiocqhttp 连接；关闭后不拦截。 |
| 保护范围 | "all" | 选择同时保护私聊与群聊，或只保护其中一种。不会修改其他会话的发送方式。 |

## 发现发送故障

结合群禁言检查和真实发送结果，判断消息能否送达。

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 检查机器人是否被群禁言 | true | 通过机器人连接查询自身的群禁言状态。关闭后主要根据真实发送失败发现问题。 |
| 同时检查全员禁言 | true | 检查群全员禁言是否影响机器人发送。需要上面的群禁言检查开启，管理员身份也参与判断。 |
| 正常群聊检查间隔（秒） | 120 | 状态正常的群多久检查一次发送权限。0 表示关闭定期检查；仍可通过其他检查与发送结果发现异常。 |
| 跟踪真实发送结果 | true | 观察主回复真正发送时的成功或失败。私聊没有通用的禁言检查接口，通常保持开启。 |
| 判定不可送达的连续失败次数 | 3 | 真实发送连续失败达到此次数后，认为该会话暂时不可送达，并暂停该会话的常规回应。 |

## 恢复与重试

发送恢复后重新开放会话。群聊可查询权限；私聊往往需要通过实际试探发送判断。

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 异常会话恢复检查间隔（秒） | 15 | 已经无法送达的会话多久检查一次恢复。群聊可检查权限，私聊恢复可能需要试探补发。 |
| 查询恢复的连续确认次数 | 2 | 禁言查询连续确认可发送后恢复。真实发送成功有实际回执，立即确认恢复；每条成功发送只记一次。 |
| 私聊补发失败后降低重试频率 | true | 私聊恢复试探连续失败时，改为间隔更久再试。通常保持开启，避免反复尝试发送。 |
| 降低重试频率前的失败次数 | 3 | 恢复试探连续失败多少次后使用下面的等待间隔。0 表示不按失败次数限制试探。 |
| 降低频率后的等待（分钟） | 10 | 达到失败次数后，每隔多久再试探补发。0 表示停止自动试探，可用“/哨兵 flush”手动补发。 |

## 积压消息补发

只补发仍在有效期内的内容。条数和时间限制避免恢复后集中发送过多旧消息。

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 待补发内容有效期（分钟） | 30 | 内容超过此时长后不再补发，避免恢复后发送已经过时的消息。 |
| 每批最多补发的条数 | 5 | 一次补发最多处理多少条有效消息。超出本批上限的内容仍留在队列，不会因此自动删除；过期内容不再补发。 |
| 两条补发消息之间的间隔（秒） | 4 | 恢复后逐条补发的最短间隔，避免积压内容同时发出。 |
| 补发前的说明文字（可选） | "" | 留空不额外发送说明。填写后会先发送这句话，例如“刚才没发出去，补给你”。 |

## 接上错过的对话

控制恢复后提供给模型的未读来信背景，不改变光谱核心的长期记忆设置。

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 恢复后提供错过的来信 | true | 恢复后的第一轮，将无法回应期间收到的消息作为背景提供给模型，帮助接上对话。它不会逐条强制回复。 |
| 错过来信的提供条数 | 8 | 恢复后最多提供多少条错过的来信。仅在提供错过来信开启时生效，增加条数会增加请求长度。 |

## 检查频率与日志

通常保留默认检查间隔，日志详情只在排查时开启。

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 后台检查间隔（秒） | 15 | 后台检查恢复与补发任务的频率，实际最短 5 秒。通常保留默认值。 |
| 记录检查详情（排查用） | false | 记录更多检查和发送状态信息，方便排查禁言或连接问题。日常保持关闭。 |
